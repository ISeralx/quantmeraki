Libro de órdenes: mejor precio

Dificultad media Python 3.12 30 min Sin resolver Ir al editor ↓

Un libro de órdenes (order book) guarda las órdenes limitadas que esperan en un mercado: las de compra (bids) y las de venta (asks). Lo primero que mira cualquier sistema de trading es el mejor precio de cada lado, es decir, la compra más alta y la venta más baja.

Escribe la clase LibroOrdenes con estos cuatro métodos:

add(order_id, side, price, qty)
Añade una orden. side es "buy" (compra) o "sell" (venta). price y qty son enteros positivos.
cancel(order_id)
Retira la orden entera. Devuelve True si estaba en el libro y False si no existe o ya se canceló.
best_bid()
Devuelve la tupla (precio, cantidad) de la mejor compra, o None si no hay compras.
best_ask()
Lo mismo para la mejor venta.

Empates y cancelaciones

  • Si varias órdenes comparten el mejor precio, la cantidad es la suma de todas ellas.
  • Al cancelar, la cantidad de esa orden sale de su nivel. Si el nivel se queda a cero, el mejor precio pasa al siguiente.
  • Cancelar un id desconocido o ya cancelado no cambia nada.
  • El libro no casa órdenes. Las pruebas nunca envían una compra a un precio igual o superior a la mejor venta, ni al revés.

Ejemplo

ob = LibroOrdenes()
ob.add(1, "buy", 100, 5)
ob.add(2, "buy", 100, 7)
ob.add(3, "sell", 103, 2)
ob.best_bid()   # (100, 12): dos órdenes a 100
ob.best_ask()   # (103, 2)
ob.cancel(1)    # True
ob.best_bid()   # (100, 7)
ob.cancel(1)    # False: ya no está
ob.cancel(2)    # True
ob.best_bid()   # None

Restricciones

  • Hasta 2·105 llamadas en total.
  • Precios entre 1 y 106 (en ticks, enteros) y cantidades entre 1 y 104.
  • Los id son enteros y no se repiten nunca, ni siquiera después de cancelar.
  • Objetivo: O(log n) por operación, aunque sea amortizado. La última prueba lo comprueba con un límite de 3 segundos.
Por qué importa

El mejor precio es la primera pieza de cualquier sistema que cotiza. Si llega tarde o mal, todo lo que va detrás decide con datos viejos.

Van en orden: de la forma del problema a la trampa que buscan las pruebas. Ninguna da la solución entera.

Pista 1

Separa el problema en dos: cuánto hay a cada precio y cuál es el mejor precio vivo. Lo primero es un diccionario. Lo difícil es lo segundo.

Pista 2

Un montículo (heap) da el mínimo al instante e inserta en O(log n). En Python, heapq solo hace montículos de mínimos: para las compras, guarda el precio con el signo cambiado.

Pista 3

Quitar un elemento del medio de un montículo es caro. No lo hagas: cuando un nivel se vacía, bórralo solo del diccionario y, al pedir el mejor precio, descarta de la cima los precios que ya no están. Cuidado con los niveles que se vacían y vuelven a llenarse.

Mírala después de intentarlo. Si la lees antes, el problema ya no te enseña nada.

La idea

Para cada lado se guardan dos cosas: un diccionario precio → cantidad total y un montículo con los precios que tienen órdenes. Otro diccionario recuerda cada orden por su id para poder cancelarla.

Cancelar solo toca diccionarios. Si un nivel se vacía, su precio se queda en el montículo como entrada caducada y se descarta la próxima vez que llegue a la cima. Esta técnica se llama borrado perezoso (lazy deletion).

import heapq


class LibroOrdenes:
    def __init__(self):
        # id -> (lado, precio, cantidad)
        self.ordenes = {}
        # por lado, precio -> cantidad total en ese nivel
        self.niveles = {"buy": {}, "sell": {}}
        self.compras = []   # montículo de -precio
        self.ventas = []    # montículo de precio

    def add(self, order_id, side, price, qty):
        nivel = self.niveles[side]
        if price not in nivel:
            # nivel nuevo: su precio entra en el montículo
            nivel[price] = 0
            if side == "buy":
                heapq.heappush(self.compras, -price)
            else:
                heapq.heappush(self.ventas, price)
        nivel[price] += qty
        self.ordenes[order_id] = (side, price, qty)

    def cancel(self, order_id):
        orden = self.ordenes.pop(order_id, None)
        if orden is None:
            return False
        side, price, qty = orden
        nivel = self.niveles[side]
        nivel[price] -= qty
        if nivel[price] == 0:
            # fuera del diccionario; el montículo, luego
            del nivel[price]
        return True

    def best_bid(self):
        nivel = self.niveles["buy"]
        # saca de la cima los precios caducados
        while self.compras and -self.compras[0] not in nivel:
            heapq.heappop(self.compras)
        if not self.compras:
            return None
        precio = -self.compras[0]
        return (precio, nivel[precio])

    def best_ask(self):
        nivel = self.niveles["sell"]
        while self.ventas and self.ventas[0] not in nivel:
            heapq.heappop(self.ventas)
        if not self.ventas:
            return None
        precio = self.ventas[0]
        return (precio, nivel[precio])

Coste

OperaciónCostePor qué
addO(log n)Un push solo si el precio es nuevo; si no, sumar en el diccionario.
cancelO(1)Solo diccionarios. El montículo se limpia después.
best_bid / best_askO(log n) amortizadoCada precio que entra en el montículo sale como mucho una vez.
memoriaO(n)Las entradas caducadas nunca superan el número de órdenes añadidas.

Aquí n es el número de órdenes añadidas hasta ese momento.

Otras formas

  • Recorrer todas las órdenes en cada consulta cuesta O(n). Con 105 llamadas se va a unos 1010 pasos y no pasa la prueba de rendimiento.
  • Una lista ordenada con bisect responde al instante, pero insertar y borrar desplazan elementos: O(n). En Python suele pasar porque mover memoria es muy rápido; en una entrevista te preguntarán por qué no es O(log n).
  • Un árbol equilibrado (o SortedDict, del paquete sortedcontainers) da O(log n) en todo y sin entradas caducadas, pero no viene con Python.

Para la entrevista

  • ¿Cómo devolverías los cinco mejores niveles de cada lado?
  • ¿Cómo añadirías modify(order_id, qty) para reducir la cantidad de una orden?
  • ¿Qué cambia si una orden que cruza el libro se tiene que ejecutar? Ese es el problema de casación.
